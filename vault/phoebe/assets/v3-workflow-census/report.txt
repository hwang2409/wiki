# phoebe v3 workflow census

## scope

- window: 2026-07-24 00:00:00 UTC through 2026-08-08 00:00:00 UTC
- source: production `app.phoebe_agent_runs`, `app.agent_items`,
  `app.phoebe_agent_run_event_items`, and `app.admin_agent_action_audits`
- included: live `general` chat and live `outreach_analysis` workflows
- included sources: web or unspecified source, Slack requests, and iMessage
  requests
- excluded: internal runs, sandbox runs, automation runs, subagent runs,
  LLM-judge conversations, Slack notifications, proactive Slack runs, and
  admin operational reports
- unit: one persisted Phoebe agent run
- PII policy: this report contains no names, phone numbers, message text,
  organization names, UUIDs, URLs, or raw trace payloads

The window is 14 calendar days. The last day is partial at the query time.
Counts are exact database counts for the stated filters.

## write-tool audit

The full ranked audit is in `workflow-census.json`. The highest-volume writes
are recommendation persistence, contact-attempt management, direct SMS, and
outreach-suggestion removal. Pending-approval counts are persisted tool-call
states, not proof that a human approved the action.

Approval-risk notes:

- Direct SMS, voice, contact attempts, start-with-contacts, and caregiver
  notifications can affect customers. They need explicit approval and a
  write-then-read verification path.
- Shift, outreach, memory, filter, playbook, sync, and availability tools can
  change agency state. They need scoped writes, idempotency, and audit receipts.
- Suggestion add/remove and outreach status tools show no pending approval in
  this sample. Confirm whether their current policy intentionally permits this.
- Incomplete outputs are common in high-volume workflows. A replay must test
  cancellation, retry, and false-success handling.

## v3 coverage findings

- covered read-only: basic caregiver, client, and shift retrieval.
- missing read/context: outreach records, contact attempts, recommendation
  state, conversation history, activity events, callouts, monitoring state,
  EHR state, playbooks, settings, and reports.
- missing write: every agency mutation and every customer communication write.
- skill/prompt gap: docs, playbooks, reporting, answer-only requests, and
  safe refusal language for unsupported writes.
- mixed: recommendation, scheduling, caregiver memory, outreach management,
  messaging, and EHR sync workflows need both context and writes.

## frequency-weighted replay dataset

Phase 2 should sample by the cluster weights above. Seed synthetic data only.
Do not replay production names, numbers, message contents, IDs, or URLs.

Required seed dimensions:

- open, filled, cancelled, recurring, and conflicting shifts
- caregivers with varied roles, languages, availability, tags, distance,
  overtime, and schedule conflicts
- clients with care-plan constraints, tags, offices, and environment limits
- outreach records with suggestions, contact attempts, no-response states,
  retries, response states, monitoring state, and staged messages
- durable caregiver and client memory rows
- conversations with synthetic recipients and approval states
- playbook rules, settings, filter rules, reports, activity events, and sync
  state
- write receipts, idempotency keys, approval decisions, cancellation, and
  retry outcomes

The machine-readable replay cases and seed requirements are in
`workflow-census.json`.

## limitations

Natural-language intent is not reconstructed. The database evidence stores
tool calls and run metadata, so clusters are tool-sequence proxies.

The census does not count raw Logfire spans. It uses persisted run and item
records, which provide unique-run counts and avoid retry inflation.
